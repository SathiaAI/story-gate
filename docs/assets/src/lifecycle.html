THE STORY LIFECYCLE

Spec in. Tested against spec. Spec out.

Four moments per story. Each one has checks a machine can verify, scored by an independent judge that is never your coding AI.

1 · READY

Fit to build?

Before any code
  • 01Story complete and sourced
  • 02No drift from PRD or TRD
  • 03Every AC has positive, negative, edge and regression tests
  • 04Upstream handoffs in place
  • 05Past learnings read
2 · CHECKPOINTS

Still on course?

Every 10 code edits
  • 06Estimated % done per AC
  • 07Drift or scope creep
  • 08TODOs and stubs
  • 09Tests keeping pace with code
  • 10Off course: stop or escalate
3 · DONE

Delivered to spec?

Before anyone says done
  • 11Code matches the ACs and the TRD
  • 12Every AC traced to tests that ran and passed
  • 13Every AC shown working in a real run
  • 14Validation report and handoff written
  • 15Learnings logged
4 · ACCEPTANCE

A human says yes

On GitHub, never by AI
  • 16CI re-runs the tests and the runs, and re-judges
  • 17Independent review, no open threads
  • 18A code owner approves the latest commit
  • 19Any new push cancels the approval
  • 20A human merges; audit flags anything else

No evidence, no pass.

Drift is never fixed quietly: it goes back to the architect and the owning session, and a human records the decision.
