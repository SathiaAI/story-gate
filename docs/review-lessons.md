# Review lessons

Mistakes that reviewers kept finding in story-gate's own pull requests, and how each one is now prevented. Read this before you open a pull request that changes story-gate. Where a lesson has an automatic check, it lives in `tests/test_gate.py` (`TestReviewLessons`) and fails the test run.

| # | Lesson | Prevented by |
|---|---|---|
| 1 | **Every new or changed function has a docstring.** Reviewers flag each undocumented function a pull request touches. | Automatic, repository-wide: the count of functions without a docstring may only go down (it can't tell which function a PR added). Per function: pre-PR checklist. |
| 2 | **A flag that needs a value refuses to run without one.** `--every` typed last used to be ignored, so the default applied without a word. | Fixed at the root: `flags()` stops with "needs a value". Automatic: every flag a command looks for in `rest` must be listed in `BOOL_FLAGS`. |
| 3 | **A test's name and docstring say what it checks.** A test called "writes only to the temp folder" only checked an error message. | Pre-PR checklist (needs judgment). |
| 4 | **Catch only the error you expect.** Retrying a "no permission" answer, or switching to another login on any exception, hides real failures. | Pre-PR checklist; the author policy (`pr_author`) only falls back when the agent App is missing. |
| 5 | **Docs quote the numbers the code enforces.** The guide said 65,000 characters; the code trims at 60,000. | Automatic: the guide's issue-size limit (60,000) and the screenshot limits are compared with the constants. Add a row when the docs quote a new limit. |
| 6 | **GitHub values reach the shell through `env:`, never inline in `run:`.** Event fields, inputs and step outputs inside `run:` can carry shell code. | Automatic: workflow templates and story-gate's workflows are scanned. Known exceptions may only be removed. |
| 7 | **A one-person repository must be able to finish every flow.** GitHub never counts an approval from whoever opened a pull request. | Fixed: setup-repo waits for CODEOWNERS before the ruleset (#75); one author policy for every pull request story-gate opens (#76). |
| 8 | **Running a setup command twice is safe, and one failed step doesn't stop the rest.** A random branch name opened a second CODEOWNERS pull request on a re-run; a refused pull request skipped the ruleset and Actions steps. | Pre-PR checklist; setup-repo uses one fixed branch and reports a failed step (#76). |
| 9 | **Data from GitHub or a tracker can have any shape; an odd shape means "unknown, play safe", never a crash.** A non-numeric approval count would have stopped setup-repo; a non-object `parameters` would have crashed it. | Pre-PR checklist; `approval_required` treats an unreadable rule as "approval needed" (#76). |
| 10 | **Checks raise errors, never `assert`; keys go only to https (or localhost) and never follow a redirect; XML is parsed with DTDs refused.** A security scan found `assert` used as a check (python -O removes it), urllib forwarding the Authorization header on redirect, and an XML parse that relied on a byte check. | Automatic: no `assert` in `.story-gate/` (`test_lesson_10_no_assert_for_checks`). Pre-PR checklist for the rest; `sg_judges.endpoint_error` / `open_url` and `sg_github._parse_xml_without_dtd` are the helpers to use. |
| 11 | **Every file one CI job hands to another: who else can write it before it is read?** A test could leave a background process that rewrote story-gate's results before upload (#83 review, fixed in T1: pull request code runs as a separate account). | Automatic on Linux: `tests/isolation_e2e.py` runs hostile tests, scenarios and budgets on a real runner (tests.yml `isolation` job). Pre-PR checklist for any new artifact. |
| 12 | **When story-gate can't read or judge an input, the check applies; it never quietly switches off.** A failed git call read as "nothing changed", a cut 2,000-character line, a binary file and an unread new file each let an enforced guardrail area skip a change (#85 review). | Automatic, by behaviour: `TestGuardrails` feeds each of these in and expects the area to apply (`test_renames_and_an_unreadable_change_make_areas_apply`, `test_unfinished_pattern_matching_never_switches_a_check_off`, `test_content_triggers_fire_on_real_added_untracked_renamed_and_deleted_files`). Automatic, by structure: working out which areas apply calls `must()`, never `git()`, which reads a failure as empty output (`test_lesson_12_...`). Pre-PR checklist for anything new: write down what happens when an input is missing, too big, unreadable or malformed. |
| 13 | **Text printed into a GitHub workflow command is escaped.** Changed file names, tracker text, API messages and workflow inputs were printed raw into `::warning` / `::error` / `::notice` lines; a line break could start a forged command, such as a fake "source verified" note the dashboard trusts (#86). | Fixed: every message goes through `gh_msg()` and every property through `gh_prop()`. Automatic: `test_lesson_13_...` refuses any other way of building a command in `.story-gate/` (any letter case, f-strings, `+` or `.format()` pieces that are printed, `sys.stdout.write`, a command after a line break inside a string, a format string kept in a variable, extra `print` arguments, `gh_msg` in a property slot where `gh_prop` is needed, an unescaped value), and a second test proves the guard catches each of those forms. `test_ci_keeps_a_forged_command_in_a_file_name_inside_one_annotation` runs `gate.py ci` on a pull request whose file name carries a forged command. Not caught automatically: a command assembled piece by piece in a variable and printed later; the pre-PR checklist covers it. `test_a_forged_verified_note_cant_be_printed_into_the_ci_log` shows the raw form forging a "verified" note and the escaped form not. Not covered: Markdown in the check's summary page (notes and problems are shown as written; see the roadmap). Budget and guardrail tables escape a run's output with `sg_measure.md()`. |
| 14 | **A safety check looks at the whole invocation, not just the program's name.** Command checks were bypassed through environment values, `$FOO` expansion and `docker run -v .:/w` (#81 review, three rounds). | Pre-PR checklist: judge an environment variable by its name, not its value; check every argument; state the boundary in the docs. Send your own security fix back to the security reviewer until a round finds nothing inside that boundary. |
| 15 | **Reading must never change what a later step does.** A note written while running `git status` changed what a later write saw (#81 review). | Pre-PR checklist: a read path writes nothing. |
| 16 | **Once pull request code has run, every later tool call on that checkout is attack surface.** story-gate's own git, run after the tests, read config the pull request had planted in a nested repository (#84 review). | Fixed: after pull request code runs, story-gate's git is locked down (`GIT_LOCKED`: no inherited `GIT_*`, no system or global config, no fsmonitor, hooks, external diff or submodules, no protocols). Automatic on Linux: `tests/isolation_e2e.py`. |

Also learned the hard way:

- GitHub's GraphQL API can report a rate limit inside an HTTP 200 answer; check `errors`, not only the status.
- GitHub ties an ETag to the token that asked, and Actions gets a new token every run, so ETags don't carry from one run to the next.
- A fresh review of the whole codebase found 7 real bugs before v0.9.0 and 13 before v0.9.1: repeat it before each release.
- CodeRabbit puts some findings only in its review summary (outside-diff items and nitpicks), not in threads: read the summary every round.
- A reviewer saying "addressed in commit X", or flagging a bug, is a claim, not proof. Run the exact case before you reply: on #85, 19 of 29 comments from one reviewer were wrong, and on #84 a thread marked addressed was not.

When a reviewer finds something new that could come back, add a row here and, if a machine can check it, a test in `TestReviewLessons`.
